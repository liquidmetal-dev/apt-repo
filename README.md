# LiquidMetal apt repository

Signed apt repository for LiquidMetal Debian packages.

## Install

```sh
sudo install -d -m 0755 /usr/share/keyrings
curl -fsSL https://liquidmetal-dev.github.io/apt-repo/liquidmetal-archive-keyring.asc \
  | sudo gpg --dearmor -o /usr/share/keyrings/liquidmetal-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/liquidmetal-archive-keyring.gpg] https://liquidmetal-dev.github.io/apt-repo stable main" \
  | sudo tee /etc/apt/sources.list.d/liquidmetal.list >/dev/null

sudo apt update
sudo apt install guest-agent
```

The repository currently publishes `guest-agent` for `amd64` and `arm64`.

## Layout

- `pool/main/g/guest-agent/` contains immutable `.deb` package files.
- `dists/stable/main/binary-amd64/` contains the `amd64` package index.
- `dists/stable/main/binary-arm64/` contains the `arm64` package index.
- `dists/stable/InRelease` and `dists/stable/Release.gpg` are signed with the LiquidMetal archive key.

Package metadata and signing files are generated by the `guest-agent` release workflow.

## Maintainer setup

Run these commands with `gh` authenticated as a LiquidMetal org/admin user.

Create a dedicated archive signing key:

```sh
gpg --batch --quick-generate-key \
  "LiquidMetal apt archive <noreply@liquidmetal.dev>" \
  rsa4096 sign 2y

gpg --list-secret-keys --keyid-format=long \
  "LiquidMetal apt archive"
```

Copy the long key ID from the `sec rsa4096/...` line, then export it:

```sh
export APT_GPG_KEY_ID="YOUR_LONG_KEY_ID"

gpg --armor --export-secret-keys "$APT_GPG_KEY_ID" \
  > /tmp/liquidmetal-apt-private.asc
```

Install the GitHub Actions secrets on `liquidmetal-dev/guest-agent`:

```sh
gh secret set APT_GPG_PRIVATE_KEY \
  --repo liquidmetal-dev/guest-agent \
  < /tmp/liquidmetal-apt-private.asc

gh secret set APT_GPG_KEY_ID \
  --repo liquidmetal-dev/guest-agent \
  --body "$APT_GPG_KEY_ID"
```

Create a fine-grained GitHub personal access token with access only to
`liquidmetal-dev/apt-repo` and `Contents: Read and write`, then store it:

```sh
gh secret set APT_REPO_TOKEN \
  --repo liquidmetal-dev/guest-agent \
  --body "YOUR_FINE_GRAINED_PAT"
```

If the GPG key has a passphrase, also store it:

```sh
gh secret set APT_GPG_PASSPHRASE \
  --repo liquidmetal-dev/guest-agent \
  --body "YOUR_GPG_PASSPHRASE"
```

Remove the exported private key from disk:

```sh
shred -u /tmp/liquidmetal-apt-private.asc
```

After setup, push a stable `guest-agent` tag such as `v0.1.0`. Prerelease tags
such as `v0.1.0-rc1` do not publish apt packages.

## Renew the signing key

If the current archive key is close to expiry and should keep the same trust
identity, extend its expiration locally and update the GitHub Actions secret:

```sh
export APT_GPG_KEY_ID="CURRENT_LONG_KEY_ID"

gpg --quick-set-expire "$APT_GPG_KEY_ID" 2y

gpg --armor --export-secret-keys "$APT_GPG_KEY_ID" \
  > /tmp/liquidmetal-apt-private.asc

gh secret set APT_GPG_PRIVATE_KEY \
  --repo liquidmetal-dev/guest-agent \
  < /tmp/liquidmetal-apt-private.asc

gh secret set APT_GPG_KEY_ID \
  --repo liquidmetal-dev/guest-agent \
  --body "$APT_GPG_KEY_ID"

shred -u /tmp/liquidmetal-apt-private.asc
```

The next stable `guest-agent` release exports the renewed public key to this
repository as `liquidmetal-archive-keyring.asc` and
`liquidmetal-archive-keyring.gpg`, then signs fresh repository metadata.

## Rotate the signing key

If the private key is compromised or the archive should move to a new trust
identity, create a new key, replace the same GitHub Actions secrets, and publish
a stable `guest-agent` release. Users must refresh their local keyring after the
new public key is published:

```sh
curl -fsSL https://liquidmetal-dev.github.io/apt-repo/liquidmetal-archive-keyring.asc \
  | sudo gpg --dearmor -o /usr/share/keyrings/liquidmetal-archive-keyring.gpg

sudo apt update
```
